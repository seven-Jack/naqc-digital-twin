# Senoo 双曝光实测采集方案

适用范围为同一套 ¹⁷¹Yb 装置、767 nm 光镊和 ³P₀ 核自旋双曝光读出协议的一个工作点。首轮建议 **m₁、m₀、空位每组各采 CAL 1,000 轮、VAL 1,600 轮**。CAL 前 100 轮/组用于检查采集链。用 CAL 冻结离线判读规则后，再开启独立 VAL 运行。 [CAL 实测模板](../references/templates/Senoo_双曝光逐轮实测模板_CAL.xlsx) · [VAL 实测模板](../references/templates/Senoo_双曝光逐轮实测模板_VAL.xlsx) · [正式验收流程](SENOO_CALIBRATION.md)

## 分批和开采顺序

| 执行步骤 | m₁ | m₀ | 空位 | 实验记录 |
| --- | ---: | ---: | ---: | --- |
| 1. CAL 先导检查 | 100 | 100 | 100 | CAL 的第一块。核对双帧 ID、时标、阈值、制备标签及原始引用。 |
| 2. 完成 CAL | 900 | 900 | 900 | 工况和记录口径一致时并入先导，累计每组 1,000 轮。先导若促成采集、ROI 或筛选口径调整，归档先导，并用最终配置重开 CAL。 |
| 3. 冻结 CAL 规则 | — | — | — | 只用 CAL 评估阈值。记录两帧阈值、比较符、协议版本、预设验收判据、CAL 工作簿哈希及冻结时间。 |
| 4. 另开 VAL | 1,600 | 1,600 | 1,600 | 使用新的采集运行及原始帧。按预定轮数完成整批后，用冻结规则统一判读。 |

1. **预登记角色和工况。** CAL 和 VAL 分开建工作簿，分别填写 `batch_role=calibration` 和 `batch_role=validation`。预登记两套不同的 `batch_id` 和 `acquisition_run_id`、角色分配时间、预定工作点、运行计划及实验用途允许的错误率上限。两批使用同一装置、协议、相机设置、ROI 映射、计数单位、计数处理和筛选口径。运行后记录实际 UTC 时间和配置快照。影响制备反馈、筛选或曝光流程的调整按新工况重新配对采集 CAL 和 VAL。
2. **在各块交错采集三组。** 每块预排三组各 100 轮，共 300 轮。CAL 的第一块已列在「CAL 先导排程」，按三轮一组交错，每组涵盖 m₁、m₀ 和空位各一次。该表保存种子和计划轮号。实际记录写入四张数据表，若设备另编轮号，在采集日志中保留对应关系。默认每轮用同一个预登记统计位点，记录重新制备或清空、复位及原子复用情况。m₁、m₀ 依据执行的制备协议登记。空位来自预安排空阱或独立占位证据，执行同一读出流程。标签在判读前登记，制备失败保留原计划标签和失败状态。
3. **先导通过后继续。** 从原始日志回查代表性正常轮的两帧、曝光窗和原机判决。若出现缺帧或制备失败，也回查对应记录。发现帧号对错、时钟漂移无法对齐或必要字段无法记录时，暂停排查并保留已发生的轮次和异常原因。
4. **锁定留出批次方案。** 在查看 VAL 结果前，登记各组固定轮数、最低可判读轮数、最低可判读位点比例、联合置信水平和八项错误率上限。八项为 m₁、m₀ 各自的错标、判丢失和歧义，以及空位误报和歧义。冻结文件和 CAL 扫描结果随批次归档。VAL 采集时按预安排轮数和记录完整性检查进度。读取结果后如需改阈值、ROI 或筛选，另留新 VAL。

### 每组轮数依据

以上是首轮采集预算。VAL 默认用每轮一个预登记位点、约 80% 轮次可判读、轮次间独立及八项指标 95% 联合置信水平估算。每组 1,600 个物理尝试预计得到 1,280 个可判读尝试，对应区间半宽约 **4.75 个百分点**。5 个百分点半宽需要至少 **1,154 个有效尝试/组**。CAL 的轮数用于取得阈值候选、检查分组计数与回收率。实际八项上限由实验用途预先定下。 [现行区间与估算公式](SENOO_CALIBRATION.md#留出批次采集量估算)

在 CAL 结束、VAL 开采前，用每组最小的「预设上限减预期错误率」作为半宽预算，并按 CAL 观察到的可判读轮比例换算物理轮数。若余量只有 2 个百分点，当前方法下需至少 7,211 个有效尝试/组，以 80% 回收率估算可预排约 9,100 轮/组。若余量为零或负值，先核对工作点与预设要求。VAL 定额完成后，样本或区间不足时报告证据不足。

一轮共享相机曝光的多个位点归入同一物理尝试。若纳入多个位点并且每轮可判读位点数不均，按 $n_{\rm eff}=(\sum_i n_i)^2/\sum_i n_i^2$ 估算有效尝试数，其中 $n_i$ 是该组第 $i$ 轮可判读位点数。分别登记可判读位点比例与可判读轮比例。运行编号和随机顺序用于追溯，尝试间独立性依据同时记录复位、原子复用、共享曝光及跨轮漂移情况。

## 原始文件与工作簿记录

CAL、VAL 各有独立运行目录。每个目录保存相机原图、采集日志、设备配置、逐轮 XLSX 和文件清单。相机原图保留仪器原始格式及帧号并单独归档。需要以计数日志作为原始来源时，留存仪器输出的逐位点计数日志和处理版本。清单列出路径、大小及 SHA-256，`raw_ref` 和其他引用按共同归档根目录解析并包含运行 ID，例如 `RUN-CAL-01/raw/cam_0001.tif#page=12`。多位点共享同一物理帧时使用同一帧引用和 `exposure_id`，各自记录 `roi_id`。

| 工作表 | 每轮或每批需填写的信息 |
| --- | --- |
| 批次配置 | `source_kind=measured`，批号、角色、采集运行、`role_assigned_at_utc`、`acquired_at_utc`。日期用带 `Z` 的 UTC ISO 8601 文本。登记 `apparatus_version`、`protocol_version`、`working_point`、`camera_config_ref`、`roi_map_version`、`count_unit`、`count_processing_ref`、`readout_rule_ref`、`outcome_policy`、`screening_rule_ref`、`clock_id` 和 `t0_ref`。多时钟附 `clock_alignment_ref`。 |
| 尝试与位点 | 每个 `batch_id + attempt_id + site_id` 一行，ID 用文本。`prepared_group` 用 `m1`、`m0` 或 `empty_control`，`prep_erasure_status` 用 `pass`、`fail`、`not_run` 或 `unknown`。保留 `analysis_status`、筛除阶段与原因、原仪器 `instrument_decision`、`decision_ready_us`、`attempt_log_ref`，有前轮依赖时填写 `previous_attempt_ref`。 |
| 曝光记录 | 每轮每位点两行，`image_no` 分别填整数 `1`、`2`。保留 `exposure_id`、`raw_ref`、`roi_id`、`raw_roi_sum`、`decision_count`、`actual_threshold` 和 `threshold_op`。`actual_threshold` 记采集当时仪器值，`ge` 表示 ≥，`gt` 表示 >，其他实际比较逻辑用 `other` 并附规则文件。保留四个时标 `trigger_us`、`exposure_start_us`、`exposure_end_us`、`count_ready_us`。 |
| 事件时标 | 按 `batch_id + attempt_id + event_id` 关联实际事件。保存 `start_us`、`end_us` 和原日志 `source_ref`，必要时填 `site_id` 和 `image_no`。制备擦除、578 nm 钟脉冲、Raman 翻转、399 nm 照明、767 nm 阱斜坡依次用 `prep_erasure`、`clock_pi`、`raman_pi`、`illumination_399`、`trap_ramp`。399 nm 照明注明对应帧。 |

统一以 `clock_id` 和 `t0_ref` 记录 µs。保留原日志的时钟刻度和换算依据。核对每帧触发 ≤ 曝光开始 ≤ 曝光结束 ≤ 计数可用，Image 2 的曝光开始不早于 Image 1 曝光结束，原判决可用时刻不早于双帧计数可用。对已登记的 399 nm 照明检查与对应曝光窗重叠。实际阈值或时标缺项时保留该轮并回查日志，供正式验收前核对。

### 缺帧、跳过与筛选

| 现场情况 | 工作簿记录 |
| --- | --- |
| 两帧正常 | 两行均 `valid`。实测零填数字 `0`。符合预设筛选规则的位点标为 `included`。 |
| 预期曝光但帧未收到 | 对应行为 `missing`，填 `frame_issue` 并保留已有时标，两列计数留空。按规则登记筛除阶段和原因。 |
| 制备失败后双帧未触发 | 保留尝试，记录 `prep_erasure_status=fail`、`analysis_status=excluded`、`exclusion_stage=preparation` 和原因。两行均为 `skipped`，填 `frame_issue`，两列计数留空。 |
| 已采图像因饱和等问题无效 | 对应行为 `invalid`，保存原图引用和已知时标，填 `frame_issue`。若筛除，登记阶段与原因。 |

保留全部物理尝试及各位点，含已经筛掉的有效帧。待定用 `analysis_status=pending` 并写原因。提交时分别汇总各组的尝试轮次、尝试位点、制备通过、双帧有效、原记录纳入、可判读及缺帧／无效／跳过。错误率以各组的可判读配对数为分母，条件为原记录纳入、双帧有效、判决计数齐全。更新阈值后的判决另存到分析报告，原始工作簿保留仪器阈值和判决。

## 核对先导轮号和分母

在本地 `#senoo` 的 **Senoo 实测工作簿**导入已填 CAL，再展开 **CAL 先导排程核对**，选择已发出的 CAL 排程模板。若设备沿用计划号，会直接按 ID 关联。设备另编轮号时，按原始日志填写并导入 JSON 对应表。对应表示例中的 `0007` 是文本。 [CAL 排程模板](../references/templates/Senoo_双曝光逐轮实测模板_CAL.xlsx)

```json
[{ "plannedAttemptId": "CAL-P-0001", "attemptId": "0007" }]
```

页面列出工作簿无对应轮、实际轮未对应排程、制备组不符及同轮多组的记录。实际轮按 `attempt_id` 计，同轮的多个位点另计。位点与帧分母按已对应排程且登记组别唯一的轮次统计。未对应的轮次可结合日志核实是设备另编轮号还是后续 CAL。工作簿有错误时同时查原表行号及记录来源。实际执行顺序、共同时标、仪器阈值和筛选仍和原始日志逐项核对。

## 交付与继续验收

- [ ] 用 CAL 先导核对一轮从制备标签、两帧到仪器判决的原始记录链，并按预定规模检查工作簿可导入。事件超过模板预排的 10,000 行范围时，可从日志按原工作表名和表头批量生成 XLSX。当前读取限额为 XLSX 24 MiB、所需解压部件合计 64 MiB，扩大量前先核对容量和导入。 [模板校验](SENOO_APPARATUS.md#导入与校验) · [读取限额](../src/data/senooMeasurementWorkbook.ts)
- [ ] 归档 CAL 的原图或计数日志、逐轮 XLSX、设备和筛选规则、文件清单及冻结 JSON。冻结和确定固定采集量后，另开 VAL 采集。
- [ ] VAL 达到预登记轮数后归档工作簿及对应原件，保存开始、结束、封存和开封记录。按原始日志复核两批工况及来源，使用冻结规则重算八项指标、分母与区间。验收依据连同独立验证报告保存。 [验证报告重算](SENOO_CALIBRATION.md#重算验证报告与关联整机)
