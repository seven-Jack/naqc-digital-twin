# Senoo 整机 Bell 独立实测采集方案

在同一套 ¹⁷¹Yb 767 nm 装置上，保持 Bell 制备、目标位点顺序和双曝光读出工况一致，交错采集 ZZ、全局 +π/4、全局 −π/4 三个设置。目标态沿用 Senoo 图 1c 的亚稳态 $(|00\rangle-i|11\rangle)/\sqrt{2}$。每组排 **3,000 次原子对尝试**，总计 **9,000 次**。以各组 80% 可用率估算，各得约 2,400 个有效轮次。默认精度目标为 95% 联合置信水平下，原始重叠估计到任一统计区间端点的距离至多 **5 个百分点**，建议每组至少 **2,155 个有效轮次**。 [空白交错排程 CSV](../references/templates/Senoo_Bell_独立实测交错排程.csv) · [Bell 观测与适用域](QUANTUM_COMPUTER.md#senoo-bell-的布居与相干) · [Senoo 图 1c](https://arxiv.org/html/2506.13632v2)

## 开采前

1. **冻结装置和制备。** 登记装置、工况、阱波长、协议、Bell 制备电路和门版本、目标位点顺序、相机配置、ROI 图、计数处理版本及共同筛选规则。只改变分析设置。保留制备脚本和控制器版本、配置文件哈希及冻结时间。开封 Bell 留出批次前冻结三组预测、容差、最低有效轮次和置信水平，归档原预测、哈希和实际封存凭据。正式预测采用同装置已核对的组件版本。 [Bell 联合预测冻结](QUANTUM_COMPUTER.md#senoo-bell-联合预测冻结与对照)
2. **核实读出。** 用同装置 CAL 选择双阈值并冻结，再用独立 VAL 验证同一规则达到预设判据。归档原 CAL／VAL 工作簿、冻结规则 JSON、独立验证报告 JSON、文件 SHA-256、读出规则版本、两个阈值及 `ge` 或 `gt`、冻结时间和工况。正式 Bell 批次使用与 CAL、VAL 分开的采集运行和原始帧。读出验证尚待完成时，用独立的调试运行核对日志格式。正式验收依赖同工况验证证据。 [双曝光标定与验证](SENOO_CALIBRATION.md#标定冻结和独立验证)
3. **标定分析轴。** 使用同一个相位参考，在两个目标位点用已知态或独立相位扫描核对 ZZ 和 $O_\phi=X\cos\phi+Y\sin\phi$。记录两位点的实际相位、相对共同零点的偏差及误差、转角及误差、实际分析脉冲的版本和时标，以及 $0\mapsto+1$、$1\mapsto-1$ 的实验依据。归档原始扫描、控制器触发或相位日志、拟合及适用时段，在 `phaseReferenceRef` 引用。采集前检查参考，采后用预定复测查漂移。实际相位和误差写入标定记录，联合 JSON 的相位字段使用模板的名义值。偏差、漂移、转角和时钟同步的限值由本装置在采集前登记。 [分析相位和 JSON 口径](QUANTUM_COMPUTER.md#senoo-bell-的布居与相干)
4. **封存排程和筛选。** 保存未填排程 CSV 和 SHA-256，登记筛选条件、输运失败和缺帧的处理、最低有效分母、联合置信水平及预先选定的精度。用 `ensembleRef` 关联跨设置共同制备、筛选口径、掩码与可比性复核。用 `independenceRef` 关联块顺序、原日志、重复制备及相邻尝试、共享设备周期和慢漂移的检查。交错可减少设置与时间顺序的耦合，统计独立性仍需用运行记录核对。调试数据分开归档，冻结后使用独立 Bell 运行。 [统计和冻结依据](SENOO_CALIBRATION.md#冻结验收判据与独立批次区间)

## 按排程采集

用同一采集运行 ID 和共同硬件时钟执行 **500 块，每块 18 轮**。每块含六个连续的三轮组，每组各测一次 ZZ、+π/4、−π/4，六种顺序各出现一次。每个设置在块内三个序位各出现两次。排程按块循环置换设置，连续两个计划轮次使用不同设置。以 CSV 行序为准。试跑测得本装置的单轮实际耗时后，再按 9,000 轮及预留的标定和中断时间确定场次。共同参考、工作点或读出配置发生改变时，记录暂停位置与原因，复核后将变更后的运行和原留出档案分别保留。

| CSV 列 | 填写与核对 |
| --- | --- |
| `schedule_version`、`block`、`slot_in_block`、`planned_id` | 预排标识。保留原顺序和 ID。 |
| `setting`、`analysis_phase_rad` | 计划测量设置和名义相位。设置对应 `population`、`plus`、`minus`。ZZ 无全局分析相位。 |
| `actual_run_id`、`actual_attempt_id` | 从运行日志填写真实采集运行和尝试 ID，联合键唯一。同一物理尝试只对应一个计划槽。 |
| `actual_setting`、`actual_log_ref` | 从执行日志填写真实设置和原始尝试引用。引用与联合 JSON 中的尝试 `sourceRef` 一致。记录计划与执行的偏差及原因。 |

四个实测字段在发出的排程中均为空。每次实际尝试都从日志填齐四列，包括装载失败、输运失败、门跳过、读出缺帧和筛除。实际设置可引用该尝试已锁定的控制器分支，分支因前段失败而跳过时，在原日志和 JSON 中保留跳过状态与原因。未触发任何尝试的计划槽留空，在运行记录中注明中断或未执行原因。出现偏离、漏采或计划外物理尝试时，保留实际记录及原因，先定位差异再形成留出结论。

| 观测组 | 计划尝试 | 80% 时预计有效 | 建议最低有效 |
| --- | ---: | ---: | ---: |
| ZZ，计算基布居 | 3,000 | 2,400 | 2,155 |
| 全局 +π/4，奇偶 | 3,000 | 2,400 | 2,155 |
| 全局 −π/4，奇偶 | 3,000 | 2,400 | 2,155 |
| 合计 | 9,000 | 7,200 | 6,465 |

每个设置以 **一轮一个预登记原子对** 计数。有效轮次要求目标电路执行成功、按已冻结筛选纳入、两位点的两帧均有效，并按冻结规则得到完整二进制位串。95% 联合水平下，按现行三项同时 Hoeffding 区间传播，原始重叠估计到任一端点的统计距离保守上界为

$$
h \le \frac12\sqrt{\frac{\ln(120)}2}\left(\frac1{\sqrt{n_{ZZ}}}+\frac1{\sqrt{n_+}}+\frac1{\sqrt{n_-}}\right).
$$

三组各 2,400 个有效轮次时，上界约为 4.74 个百分点。每组排 3,000 轮时，达到各组 2,155 的最低有效率约为 71.83%。若精度预先改为 3 或 2 个百分点，三组等样本预算分别为每组至少 5,985 或 13,465 个有效轮次。按块核对覆盖、时标和缺失，完成预定排程后一次性评估重叠。若未达到原定有效轮数或出现漂移、筛选不一致，记录短缺和受影响的结论。需要补测时先登记新的独立排程和分析规则，按运行分别导入和核对。跨运行合并需要预先确定分析口径。区间的统计精度和正式验收容差分开登记，分析轴、筛选和读出系统偏差由各自的实测证据约束。 [区间实现](../src/physics/senooBellObservations.ts)

## 逐轮归档

| 保留的原始资料 | 每轮应能回查的字段 |
| --- | --- |
| 运行、控制器与阶段日志 | 计划 ID、实际尝试 ID、实际设置、原始记录路径或内部行号、装载前后及输运后占位、目标位点顺序、装载／输运／门／读出各阶段执行状态、起止时刻、失败与跳过原因。实际分析脉冲的相位、开关时刻和共同参考通过原日志关联该轮与所在校准时段。 |
| 每个相机曝光的原件 | Image 1 与 Image 2 的实际曝光 ID、原图或可回查的相机原始记录、相机配置与曝光参数、原件哈希。两帧的触发、曝光起止、计数可用时刻及仪器判决时刻沿用共同硬件时钟。保留 `clockId`、`timeOriginRef`、源时钟刻度和换算关系，JSON 中的时标用秒。核对触发 ≤ 曝光开始 < 曝光结束 ≤ 计数可用，且 Image 2 的曝光开始不早于 Image 1 结束。 |
| 每个位点各两条 ROI 记录 | 按实际尝试、位点和 Image 应用 ROI，记录曝光 ID、ROI ID、原图或计数日志引用、计数及单位、有效／缺帧／无效／跳过。两位点共用同一相机曝光时，触发与曝光时标一致，ROI ID 各自唯一。有效零计数照实填 0，缺帧或跳过的计数留空，两个帧槽都保留。 |
| 原阈值、仪器判决与筛选 | 保存每帧仪器当时使用的实际阈值、`ge` 或 `gt`、仪器规则版本和每位点原判决。另存冻结规则对原始计数的重算结果及版本。按尝试记录筛选掩码、纳入或排除、原因及证据引用，筛除的原始帧照常保留。 |

逐设置汇总计划数、实际尝试、输运后双位点就绪、目标电路已执行、读出已尝试、两位点双帧齐全、执行且纳入、纳入且双帧齐全、纳入且可判读。将缺帧／无效、双暗判丢失和双亮歧义各自列出。双暗和双亮项以两位点双帧齐全的已执行尝试为分母，可出现在同一轮的不同位点。布居和奇偶使用本设置的纳入且可判读分母。归档共同筛选的逐轮掩码，按设置和时间块对照纳入率、缺帧率与判读率。 [整机计数口径](QUANTUM_COMPUTER.md#senoo-独立电路批次)

## 导入与交付

1. 在 `#senoo → 整机电路独立批次 → Bell 布居与相干核对` 使用 **下载 Bell 交错排程 CSV** 下载排程副本。用 **下载 Bell 观测模板 JSON** 取得联合模板，用上一级的 **下载整机批次模板 JSON** 取得单设置批次结构。填写联合 JSON 的三个 `batch`，ZZ 声明 `basis=ZZ`，两组相位声明各自旋转参考框架的 `basis=XX`。三组使用同一真实运行和时钟，分别给不同的 `batchId`，`expectedAttempts` 按该组实际尝试总数填写。标记 `sourceKind=measured`，三组齐全后保存。 [联合与单批次字段](QUANTUM_COMPUTER.md#senoo-bell-的布居与相干)
2. 用 **导入 Bell 排程 CSV** 导入已填排程，用 **导入 Bell 观测 JSON** 导入联合文件。对照三组实际尝试和计划覆盖，核对轮号、实际设置、源引用、执行顺序和重复或未关联轮次。见到缺号、组别不符或时序异常时，用原日志核查，修正录入并保留修订记录。实测文件在上一级另用 **导入整机用读出冻结规则 JSON** 和 **导入整机用读出验证报告 JSON** 关联冻结证据。 [读出报告重算与关联整机](SENOO_CALIBRATION.md#重算验证报告与关联整机)
3. 用 **导出 Bell 观测核对 JSON** 归档观测、各组分母及其对冻结预测的残差和区间。提交未填与已填的排程、联合观测 JSON、原始日志和帧清单、分析相位标定、冻结预测、冻结读出及独立验证报告、逐轮筛选记录、异常复查结果和核对报告。文件清单登记版本、来源、SHA-256 和原件路径。合成导入和现场实测分别归档。正式验收按已冻结的独立批次及证据评估。 [项目验收要求](SENOO_CALIBRATION.md#六项验收所需证据)
