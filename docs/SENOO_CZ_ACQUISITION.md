# Senoo 两原子 CZ 实测采集与核对

本轮先准备同一门版本的三套记录，即双位点实际波形、独立门响应和独立 gRB／丢失。适用范围为 ¹⁷¹Yb、302 nm 里德堡驱动的双位点 CZ。先导排程用于核对控制器、时标和文件接口，实测结果栏留空。双曝光 CAL 本轮暂缓。正式验收使用同工况、经过独立验证的读出或态分辨、存活标定证据。 [CZ 模型和表征口径](SENOO_CALIBRATION.md#两原子-cz-波形与关联记录)

## 1. 冻结工况与波形

1. 从实验配置登记 `apparatusVersion`、`gateVersion`、`workingPoint`、两个有序 `siteIds` 及采集运行 ID。归档实际控制程序、编译器版本和参数、门版制品及 SHA-256。波形、门响应和 gRB 一律沿用已核对的门工况，分别保存运行和原始记录。波形采集使用独立运行，响应和 gRB 分别登记试验协议及其采集划分。
2. 以共同时钟同步保存控制器触发、门起止和两个位点的 Ω、Δ、φ。保留 RF／AOM 或光学监测原件、源单位、传递标定、适用时段和不确定度，从监测量换算到原子处驱动。记录采样间隔、窗内缺段、失谐零点和符号、相位零点及展开方式。时标转为 s，Ω 和 Δ 转为 rad/s，φ 用 rad。填写旋转框架时核对相位调制只计一次。 [波形字段和约定](SENOO_CALIBRATION.md#json-v1-字段)
3. 保存位点间距、连线与磁场夹角、磁电场及同工况带符号相互作用频移 $V_{\mathrm{Hz}}$ 的原始标定和误差，另存阱、擦除、电离、局部 Z 补偿的实际时序及状态。原件登记文件路径、SHA-256、时钟或触发编号，以及供回查的样点或日志行。 [公开约束与原始记录缺项](../references/knowledge/senoo-cz-reproduction.md#波形证据与仍缺的原始记录)
4. 在 `#senoo → 图 3b–d CZ 表征 → 两原子 CZ 波形输入` 点 **下载 CZ 波形模板 JSON**，填好后用 **导入 CZ 波形 JSON** 核对工况与门窗。冻结输入文件的原始字节并登记 SHA-256。冻结时可将 `responseDataRef` 留为 `null`，随后在独立归档清单中记录响应和 gRB 的文件哈希、运行 ID 与冻结波形的关联。保留冻结 JSON 原字节。用 **核对相干演化** 和 **导出相干计算 JSON** 归档传播选项、步长细化诊断及返回、泄漏、条件相位的预测。在查看留出结果前确定模型版本、容差和判据。 [相干计算和适用范围](SENOO_CALIBRATION.md#两原子-cz-的相干前向模型)

## 2. 独立门响应

先导 **48 次原子对尝试**，按 CSV 行序交错制备 `00`、`01`、`10`、`11`。每块四种输入各一次，每种合计 12 次。每轮用一个预先指定的有序原子对，0、1 对应 m₀、m₁。设备运行号、轮号、实际制备、制备筛选和原始记录从现场日志填写。未触发的计划槽保留空白，已触发但制备筛除的尝试记 `rejected`，结局留空。 [空白门响应先导排程](../references/templates/Senoo_CZ_独立门响应先导排程.csv)

- 表格软件导入 CSV 时将 `planned_input`、`actual_input` 设为文本，保留 `00` 和 `01` 的前导零。用 `actual_run_id` 与 `actual_attempt_id` 关联设备记录，实际制备、筛选、结局填入 `actual_input`、`actual_prep`、`actual_outcome`，从 `actual_log_ref` 回查原件。
- 按原始尝试 ID 保存门前占位、实际制备与筛选、脉冲事件和门末观测。门末能确认的结果分别登记原逻辑态返回、其他逻辑态、里德堡泄漏、第一或第二位点丢失、双位点丢失、歧义或不可用。若采用双曝光，保留两个曝光 ID、原帧、共同触发与曝光边界、计数可用时刻、两位点 ROI、计数和实际判决设置。里德堡泄漏须有对应的态分辨证据，物理丢失须回查逐位点存活证据。缺帧、双暗及歧义按实际可分辨程度登记。
- 条件相位另采干涉数据。可用共同参考下的 Ramsey 测量，分别比较旁观位点处于 0 和 1 时的目标位点相位。保留分析相位、单轮观测、拟合模型、残差和区间，核对位值、相位正负与 $\arg(A_{11}A_{00}/(A_{10}A_{01}))$ 一致。归档分析脉冲实际时序、读出标定与漂移复核。相位数据齐备后再填响应 JSON 的 `phase`。
- 打开 **两原子 CZ 独立门响应**，用 **下载 CZ 门响应模板 JSON** 取得字段。填写唯一物理轮号、制备和筛选标签、原始记录引用及 `waveformSha256`。导入已经计算的同门波形后，用 **导入 CZ 门响应 JSON** 检查位序、门版本和运行独立性，用 **导出 CZ 门响应核对 JSON** 归档各组尝试、纳入和未判明分母、概率与条件相位残差。 [独立门响应字段及统计](SENOO_CALIBRATION.md#两原子-cz-独立门响应)

## 3. 独立 gRB 与丢失

先导 **24 次原子对尝试**，按图 3b 的深度选择，在四个区块交错安排 0、4、8、12、16、20 个 CZ 的六种深度。每块覆盖六种深度，每种合计四次。零深度保留制备和读出对照。开采前用已验证编译器生成与实际门版本匹配的线路，填好 `sequence_id`、`seed` 和 `target_bitstring`，将种子及目标位串作为文本保存。冻结实际门数、编译产物和哈希。登记本批是 `non-echo` 还是 `echo`，图 3b 的描述性拟合对应非 echo。 [空白 gRB／丢失先导排程](../references/templates/Senoo_CZ_gRB_丢失先导排程.csv) · [图 3 源表](../references/knowledge/data/senoo-fig3-cz-by-depth.csv) · [Senoo 图 3 与 Methods](https://arxiv.org/html/2506.13632v2)

- 每次尝试从原日志关联真实轮号、线路、采集块、有序位点和原子对 ID。正式批次同一物理轮次若读出多个原子对，各对分别登记且共用采集块。按真实共享曝光、线路重复和慢漂移证据确定块内依赖。先导排程的区块用于安排运行顺序，统计独立块按采集证据登记。
- 保存三个逐轮掩码 `prep`、`decay`、`loss`，分开核对各筛选条件、纳入计数和交集。保存观测位串及逐位点 `present`、`lost` 或 `unknown`，有确定状态时记录 `survivalRef`。原始相机记录、仪器阈值、判决版本、掩码版本及实际触发应能从轮号回查。三种成功率各用相应纳入原子对作分母，单站点丢失用制备擦除组的位点数，双位点丢失用同组原子对数。结局未判明时保留计数范围。
- 打开 **CZ gRB 与丢失独立批次**，用 **下载 CZ gRB 模板 JSON** 取得字段。用 **导入 CZ gRB 批次 JSON** 核对冻结波形哈希、同门身份、深度、种子、位点和分母，用 **导出 CZ gRB 核对 JSON** 归档结果。 [gRB 与丢失字段及统计](SENOO_CALIBRATION.md#独立-grb-与丢失批次)

## 4. 先导通过与正式采集量

先导逐行核对计划和控制器日志，确认可还原实际输入或深度、共同时钟、筛选和结局。检查失败、缺测、重复 ID 与分母变化是否如实进入报告，保留偏离、补录和修订记录。先存完整原件及报告，再登记正式批次的参考相位、允许误差、筛选口径、最低分母、未判明结局上限和停止规则。

按现有统计口径，以 95% 联合置信水平、每项概率的统计扩展半宽至多 5 个百分点为预算示例。独立门响应需每个输入至少 **1,154 个门前纳入轮次**。gRB 含六个预登记深度时，每个深度和指标需达到 **1,419 的有效块数**，用 $N_{\mathrm{eff}}=N^2/\sum_i n_i^2$ 核对，其中 $n_i$ 为该块在该指标的有效单位数，$N$ 为各块有效单位之和。实际计划尝试数还要按先导纳入率、块大小和丢失估算。未判明结局造成的额外范围、相位误差、标定和模型系统误差分别预算。每门保真度或丢失斜率的不确定度另用正式采集设计和独立重复评估。 [门响应区间](SENOO_CALIBRATION.md#两原子-cz-独立门响应) · [gRB 同时区间](SENOO_CALIBRATION.md#独立-grb-与丢失批次)

正式交付包含冻结波形原件和预测、已填排程、逐轮记录与帧清单、独立门响应与 gRB JSON、所用读出及存活标定、两份核对报告及含各文件哈希的关联清单。用同工况实测检验已冻结预测，按预设容差分别报告门响应、条件相位、gRB 和丢失。 [正式验收条件](SENOO_CALIBRATION.md#六项验收所需证据)

## 5. 本地交付核对

从项目根目录运行。将示例的文件名换为本批三份 JSON 和两份已填排程 CSV 的路径。保留发出的计划轮号、区块、顺序及输入或深度。先归档采集前填有线路 ID、种子和目标位串的 gRB 排程副本及其 SHA-256，再依据设备日志填写两份排程的实际列。实测原始引用和时序按设备日志复核。

```sh
cz_audit_dir=$(mktemp -d)
./node_modules/.bin/esbuild scripts/audit-senoo-cz-acquisition.ts \
  --bundle --platform=node --format=esm --outfile="$cz_audit_dir/audit-senoo-cz-acquisition.mjs" &&
node "$cz_audit_dir/audit-senoo-cz-acquisition.mjs" \
  "waveform.json" "response.json" "benchmark.json" \
  --response-schedule "response-filled.csv" \
  --benchmark-schedule "grb-filled.csv" > "$cz_audit_dir/cz-acquisition-audit.json"
```

两个排程参数可分别使用。省略时沿用三份 JSON 的文件关联核对。`inputs` 保留本次读取文件的路径和 SHA-256，`scheduleAudit` 保存每份排程的逐轮核对。

| 报告字段 | 复核内容 |
| --- | --- |
| `totals`、`rows`、`unplanned` | 分别列出计划、实际列已登记、完全匹配、未登记计划轮、冲突及未关联实际记录。每条差异保留计划轮号、原始日志引用、字段、预期和实际。重复关联会指出全部涉及轮号。 |
| 门响应 `groups` | 按运行和尝试 ID 关联。按输入保留全批与匹配轮次的启动、门前纳入、筛除、歧义或不可用，以及已确认的物理丢失。响应概率的保守范围另沿用包含物理丢失的未判明计数口径。 |
| gRB `groups`、`batchStatistics`、`matchedStatistics` | 按运行、尝试与原子对 ID 关联。核对线路 ID、深度、种子、目标位串和实际分析块，保存三个掩码、存活证据及线路出处。分别保留全批与匹配子集中每个深度的三种筛选分母、单站点丢失的位点分母和双位点丢失的原子对分母。 |

出现漏轮或冲突时保留全批及匹配子集两份统计，子集用于定位问题。完整关联结果标为 `linked`。哈希、工况、记录关联或排程出现差异时输出 `mismatch`，退出码为 1。文件无法读取或解析时退出码为 2。按 `reviews` 回查相位参考、位点和采集依赖。正式验收以同门版本的原始证据和预设判据为据。 [本地核对脚本](../scripts/audit-senoo-cz-acquisition.ts)
